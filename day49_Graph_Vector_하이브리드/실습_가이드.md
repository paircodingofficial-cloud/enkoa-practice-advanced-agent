## 0. 준비

- [ ] 필요한 패키지를 설치합니다.


- [ ] `.env.example`을 `.env`로 복사하고 본인의 API 키·DB 연결 정보를 입력합니다.

- [ ] 교안 02용 GDS·APOC를 준비하고 README의 Cypher 버전·실습 계정 조건을 확인합니다.
- [ ] `data/embeddings/movies_complete.npz`가 있는지 확인합니다. 문서 임베딩을 다시 생성하지 않습니다.
- [ ] 노트북 파일이 있는 폴더에서 시작합니다.
- [ ] 마지막 **핵심 코드 이어서 보기**는 본문의 DB 적재를 마친 뒤 실행합니다. 검색·답변에 필요한 연결과 함수가 포함되어 있습니다.

## 1. 교안 01을 진행합니다

- [ ] **준비한 영화 자료를 연결합니다:** 원문과 청크·벡터의 대응, `Movie`·`Person`·`Document`·`Chunk`의 연결 구조를 확인합니다.
- [ ] **실습 질문의 목적을 확인합니다:** 줄거리로 기준 영화를 찾고, 공통 배우의 다른 출연작까지 요청한 상황입니다.
- [ ] **1. 진입 청크와 최종 문서를 구분합니다:** 청크 수와 고유 문서 수를 따로 읽습니다.
  - [ ] 조난 줄거리로 `practice_vector`·`practice_seeds`를 만듭니다.
- [ ] **2. VectorCypherRetriever로 다른 영화까지 확장합니다:** 관계 방향과 `seed_score`의 의미를 확인합니다.
  - [ ] 조난 이야기의 `practice_expanded`에서 진입 청크와 출연 경로를 확인합니다.
- [ ] **3. Neo4j 전문 검색을 같은 원문 ID로 연결합니다:** 한글 질문에서 변환한 검색어를 읽고 반환 단위를 통일합니다.
  - [ ] `practice_fulltext`와 `practice_seeds`의 공통·차이 ID를 확인합니다.
- [ ] **이번 강의 정리:** 청크·문서·경로의 중복을 구분해 설명합니다.

## 2. 교안 02를 진행합니다

- [ ] **준비한 영화 자료를 연결합니다:** 새 커널에서 준비 셀부터 시작합니다.
- [ ] **1. 줄거리와 관계 조건을 나누어 검색합니다:** Text-to-Cypher가 생성한 Cypher와 반환한 후보·출연 근거를 읽습니다.
  - [ ] Apollo 13·1999~2000·공유 배우 조건의 `practice_graph_rows`에서 후보와 출연 근거를 함께 받습니다.
- [ ] **2. 전문·벡터 검색을 합치고 관계 후보를 남깁니다:** EnsembleRetriever로 두 순위를 합친 뒤 graph_rows의 ID로 후보를 제한합니다.
  - [ ] 같은 조회 결과로 전문·벡터 통합 후보와 관계 검색으로 보완한 후보를 비교합니다.
  - [ ] 섬 생존 질문의 `practice_candidates`를 만듭니다.

- [ ] **3. 영화의 PageRank를 검색 순위에 반영합니다:** 전체 영화 PageRank의 중앙값을 기준으로 포화 점수를 만들고, 검색 순위 점수와 결합해 비중을 비교합니다.

  - [ ] 본문과 목록 양쪽의 인용 ID를 비교하고, 인용이 비어 있지 않은지 확인합니다.
  - [ ] `practice_answer`의 인용 ID와 실제 원문을 읽습니다.
- [ ] **이번 강의 정리:** 누락이 생긴 단계를 찾아 설정 하나를 바꾸는 방법을 설명합니다.

## 4. 의료 과제 LV1을 풉니다

- [ ] 구분선 안 `[작성]`에서 `변수명 = ...`의 우변 전체를 작성합니다. 조건문·갱신문은 `...` 자리에 전체 문장을 작성하며, 방법은 요구사항에 있습니다. 준비·함수 틀·표·출력은 제공됩니다.

과제 맨 위의 의료 그래프를 확인하고, 준비 셀에서 14개 문서·43개 청크와 배포 벡터를 적재합니다. 교안 01의 순서를 그대로 따라갑니다.

- [ ] 1. 벡터 검색기를 만들고 청크를 찾습니다
- [ ] 2. 청크 결과를 원문별로 합칩니다
- [ ] 3. 공통 효능 증상으로 다른 제품까지 확장합니다
- [ ] 4. VectorCypherRetriever에 확장 쿼리를 연결합니다
- [ ] 5. 중복 제품의 효능 경로를 보존합니다
- [ ] 6. 후보의 효능 경로와 원문을 확인합니다
- [ ] 7. Jev 언어 판단을 전문 검색에 연결합니다
- [ ] 8. 검색 방식별로 찾은 원문을 비교합니다

## 5. 의료 과제 LV2를 풉니다

교안 02의 순서를 따릅니다. 새 커널에서 준비 셀을 실행하고, 게보린정과 공통 효능 증상·임부 주의 기록이 있는 제품의 원문을 찾습니다. 관계 조건은 자연어 graph_request에 담고, Text-to-Cypher의 graph_rows에서 후보와 근거 ID를 함께 받습니다. 이 후보 ID로 통합 결과를 제한합니다.

- [ ] 1. 원문 요구와 관계 조건을 나누어 검색합니다
- [ ] 2. GraphCypherQAChain으로 관계 후보를 찾습니다
- [ ] 3. 생성 쿼리의 후보와 관계 근거를 확인합니다
- [ ] 4. EnsembleRetriever로 전문·벡터 검색을 합칩니다
- [ ] 5. 관계 조건으로 제한하고 검색 누락 후보를 보완합니다
- [ ] 6. 효능 그래프의 PageRank를 계산합니다
- [ ] 7. 같은 후보에서 PageRank 비중을 비교합니다: 문서 제품 14개의 중앙값으로 포화 점수를 계산합니다
- [ ] 8. 멀티홉 결과를 원문과 관계 근거로 재구성합니다
- [ ] 9. 근거를 인용하는 답변 체인을 작성합니다
- [ ] 10. 인용 원문과 답변의 주장을 대조합니다

## 막혔을 때

- 파일을 찾지 못하면 작업 디렉터리와 `material_dir`를 확인합니다.
- 배포 벡터 대응 오류가 나면 같은 버전의 `data/` 전체를 다시 확인합니다. 자동 재임베딩으로 넘기지 않습니다.
- Neo4j 인증 오류는 `.env`의 `NEO4J_URI`·`NEO4J_USER`·`NEO4J_PASSWORD`를 확인합니다.
- APOC·GDS 프로시저를 찾지 못하면 서버의 플러그인 설치 상태를 확인합니다.
- 관계 결과의 `source_id`가 없으면 생성 Cypher의 `RETURN d.id AS source_id`를 확인합니다.
- LLM의 질문 해석에는 오류가 있을 수 있습니다. 생성 Cypher와 실제 근거를 읽고, 교안은 영화·연도·공유 배우 수를, 과제는 기준 제품·공통 효능 증상 수·주의 대상과 관계 방향을 확인합니다.
- 전문 검색이 비어 있으면 ONLINE 상태와 검색어를 확인합니다. 교안은 movie_fulltext·english, 과제는 drug_fulltext·standard-no-stop-words를 사용합니다. 과제의 한글 질문은 변환하지 않습니다.

### 검색 결과에 원문 ID가 없을 때

`KeyError: None`이 발생하면 최신 교안을 받아 커널을 재시작하고 적재 셀부터 실행하세요. 영화 전용 `Day49MovieChunk` 인덱스로 바꾼 뒤 검색기와 모든 검색 결과를 다시 만듭니다. 열린 노트북에 적용할 코드는 `영화_검색범위_수정.txt`를 참고하세요.
