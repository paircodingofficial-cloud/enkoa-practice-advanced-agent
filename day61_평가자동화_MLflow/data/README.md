# 데이터 안내

이 폴더에는 두 교안이 함께 쓰는 데이터가 있습니다. 본 실습은 **수업용 가상 자료**인 「한빛구립도서관 이용 안내」를, 따라하기는 **실제 공공 문서**인 고용노동부 「2024 유연근무 활용 매뉴얼」 발췌를 사용합니다. 모든 파일은 검증을 마친 결과이므로 직접 고치지 않습니다.

| 파일 | 개수 | 내용 |
|---|---:|---|
| `본실습/docs.jsonl` | 15개 | 가상 도서관의 대출·반납·연체·예약·상호대차·시설·회원 안내문 |
| `본실습/golden.jsonl` | 16건 | 도서관 이용 질문 골든셋 (단일 사실 8, 여러 문서 결합 4, 예외·조건 2, 자료에 없는 질문 2) |
| `따라하기/docs.jsonl` | 44절 | 유연근무 활용 매뉴얼 발췌 (공통 11, 시차출퇴근 9, 선택근무 9, 재택근무 15) |
| `따라하기/golden.jsonl` | 24건 | HR 상담 질문 골든셋 (원천 질문 82개 중 선별 20건과 직접 쓴 답변 불가 4건) |
| `manifest.json` | 파일 4개 | 각 파일의 SHA-256과 행 수, 빌드 원본의 SHA-256 |

## 본 실습: 한빛구립도서관 이용 안내

한빛구립도서관과 그 규칙은 수업을 위해 지어낸 가상 자료이며 실제 도서관의 정보가 아닙니다.

규칙의 숫자는 일부러 서로 헷갈리게 설계했습니다. 일반 도서는 7권·14일, 신간 코너 도서는 3권·7일, 어린이 회원은 5권·14일이고, 연장은 1회 7일, 상호대차 도착 후 보관도 7일입니다. 한 문서만 읽으면 답이 반쪽이 되는 규칙도 있습니다. 예를 들어 상호대차 안내는 대출 기간이 "일반 도서와 같다"고만 적고 14일은 일반 도서 대출 안내에만 있습니다.

문서 필드

| 필드 | 설명 |
|---|---|
| `doc_id` | 문서 ID (영문 소문자와 하이픈, 예: `loan-basic`) |
| `title` | 안내문 제목 |
| `text` | 안내문 본문 (2~5문장) |
| `category` | 대출, 반납, 연체, 예약, 상호대차, 변상, 희망도서, 회원, 운영, 시설 중 하나 |
| `updated` | 안내문 최종 수정일 |

## 따라하기: 유연근무 활용 매뉴얼 HR 상담 챗봇

원문은 고용노동부 「2024 유연근무 활용 매뉴얼」입니다. 원본 PDF는 [고용노동부 일·생활 균형 누리집의 게시 페이지](https://www.worklife.kr/website_renew/index/newsroom/press_releases_view.asp?GUID=B1C5B341-D745-40C5-9D6B-769F3D75E921)에서 받을 수 있습니다. 44절 발췌와 질문 82개는 day47(하이브리드 검색·질의 변환)에서 만들어 day48(리랭킹·컨텍스트 압축)이 그대로 옮겨 쓴 자료이며, 이 폴더는 `day48_리랭킹_컨텍스트압축/data/`의 `practice_docs.json`과 `practice_questions.json`에서 다시 옮겨 왔습니다.

문서 본문은 한 글자도 바꾸지 않았습니다. 빌드할 때 각 절의 본문 SHA-256을 day48 `sources.json`의 기록과 대조하고, 원천 질문 82개의 근거 101개가 모두 `text[start:end]`와 정확히 같은지 확인합니다. 원문에는 PDF에서 옮겨 온 가운뎃점 변형(`･` U+FF65 73회, `∙` U+2219 18회)과 글자 사이 공백이 그대로 남아 있습니다. 인용을 원문과 대조할 때는 정규화가 필요합니다.

문서 필드

| 필드 | 설명 |
|---|---|
| `doc_id` | 절 ID (예: `hr_approval`) |
| `title` | 절 제목 |
| `text` | 매뉴얼 원문 발췌 |
| `url` | 원문 게시 페이지 주소 |
| `source` | 문서명, PDF 쪽, 인쇄 쪽 |
| `metadata.category` | 수업용 분류 (공통, 시차출퇴근, 선택근무, 재택근무) |
| `metadata.pdf_page` | PDF 뷰어에서 1부터 센 쪽 (인쇄 쪽수와 다름) |

선별 기준은 네 범주를 고루 담고, 근거가 두 절에 걸친 질문(원천에 있는 4건 모두)을 넣고, 대상 제외·요건·기간 같은 조건과 예외가 들어간 질문을 우선한 것입니다. 질문 문장과 `question_id`, 참고 답안, 근거는 원천 그대로입니다. 답변 불가 4건은 유연근무와 관련 있어 그럴듯하지만 44절 어디에도 답이 없는 질문으로 직접 썼고, 빌드할 때 핵심 검색어가 원문에 0번 나오는지 확인합니다.

## 골든셋 필드

두 골든셋 모두 같은 여섯 칸입니다. 질문, 정답 답변, 정답 근거로 이루어진 골든에 사례 키, 정답 근거 문서 ID, 빠른 점검 표시를 더했습니다.

| 필드 | 설명 |
|---|---|
| `case_id` | 사례 키 (`lib-01`, `hr-01` 형식). 평가 결과의 순서가 바뀌어도 이 키로 사례를 맞춥니다 |
| `input` | 사용자 질문 |
| `expected_output` | 정답 답변 문장. 자료에 없는 질문은 챗봇의 안내 문장(본 실습 "제공된 이용 안내에서 확인할 수 없습니다.", 따라하기 "제공된 매뉴얼에서 확인할 수 없습니다.") |
| `context` | 정답 근거 문장 목록(본 실습은 근거 문서 본문, 따라하기는 원천 근거 구간). 자료에 없는 질문은 내용이 없다는 한 줄 |
| `relevant_doc_ids` | 정답 근거 문장이 나온 문서의 `doc_id` 목록. 자료에 없는 질문은 빈 목록 |
| `smoke` | 빠른 점검용 묶음이면 true (본 실습 6건, 따라하기 8건, 질문 유형 네 가지를 모두 포함) |

본 실습의 정답 답변은 사람이 근거 문서의 표현대로 썼고, 따라하기는 원천 참고 답안을 그대로 썼습니다. 본 실습의 여러 문서 결합 질문은 근거 문서 하나만으로는 답이 완성되지 않도록 만들었고, 빌드할 때 이를 확인합니다(검색 결과를 1개만 넘기면 답이 불완전해집니다).

노트북에서는 `doc_id`를 **근거 ID**라고 부르고, Chroma 문서의 metadata `source_id`에 같은 값을 넣어 `evidence_id(doc)`로 읽습니다.
