# CRAG·Self-RAG 실습

기존 검색 결과를 평가·보완하고, 생성 답변을 검토·수정해 근거가 남는 업무 초안을 만듭니다. 커리큘럼과 공식 문서를 대조한 기준일은 **2026-10-01**입니다.

## Agentic RAG와의 관계

Agentic RAG는 LLM 기반 에이전트가 상황에 따라 언제, 어떻게 검색할지 결정하는 RAG 방식입니다. day53에서는 CRAG·Self-RAG의 아이디어를 활용해 검색·답변을 평가하고 재검색·수정·보류를 선택하는 워크플로를 배웁니다. 첫 검색과 가능한 경로는 미리 설계합니다. 두 교안 맨 위에 개념과 구현 범위의 차이를 설명했습니다. [LangChain 공식 분류](https://docs.langchain.com/oss/python/deepagents/retrieval)

## 필요 라이브러리와 환경 설정

저장소 루트의 uv 프로젝트에서 필요한 패키지를 설치하고 같은 환경을 Jupyter 커널로 선택합니다.

```bash
uv add -r day53_CRAG_SelfRAG/requirements-day53.txt
```

주요 패키지는 `langgraph`, `langchain-openai`, `langchain-core`, `langchain-community`, `langchain-classic`, `langchain-chroma`, `chromadb`, `rank-bm25`, `kiwipiepy`, `numpy`, `pydantic`, `python-dotenv`, `requests`입니다. 세부 버전 범위는 [requirements-day53.txt](requirements-day53.txt)에 있습니다.

`.env`의 `OPENAI_API_KEY`, `OPENAI_CHAT_MODEL`은 day51·52 설정을 사용합니다. 기존 환경변수와 `.env`는 덮어쓰지 않습니다. 새 커널에서 각 노트북을 위부터 진행하세요. 교안은 단원 폴더에서 실행합니다. 정답과 해설은 강사가 공유합니다.

`.env`에 `TAVILY_API_KEY`를 설정합니다. 공개 영화 자료는 내부 재검색 뒤에도 근거가 부족하면 Tavily 웹 검색으로 보완합니다. 키 누락·연결 오류 등으로 웹 검색에 실패하면 결과를 가져오지 못했다는 안내를 남기고 기존 근거로 답변을 이어갑니다. 쓸 근거가 없으면 확인 불가를 안내합니다. 가상 사내 규정에는 웹 검색을 사용하지 않습니다. 실제 LLM 호출이 필요하며 고정 응답 캐시로 대신하지 않습니다.

## 결과 확인 기준

- 원질문을 보존하며 검색 표현만 수정했는지
- 이전에 찾은 유효 근거가 재검색 뒤에도 남는지
- 단순 관련성과 질문 전체의 충분성을 구분했는지
- 답변이 예외·기한·적용 조건을 빠뜨리거나 해결을 보장하지 않는지
- 수정 입력에 직전 초안과 검토 의견이 전달되는지
- `output/`의 Markdown·JSON에 답변, 실제 인용, 선택 근거, 검색·검토 기록이 남는지

한 문의당 검색어 재작성 최대 1회, 웹 검색 최대 1회, 답변 검토 최대 2회, 수정 최대 1회입니다. `recursion_limit`은 별도의 실행 단계 한도입니다.

`generated`는 전체 답변 초안, `accepted`는 전체 답변의 모델 검토 통과, `partial`은 미확인 사항이 남은 부분 답변, `insufficient`는 쓸 근거 없음, `review_failed`는 검토 미통과입니다. `partial`도 교안 02에서는 답변 검토를 거칩니다. 확인된 내용은 인용과 함께 안내하고, 미확인 사항과 추가 확인 방법을 명확히 알립니다. 저장 결과는 초안과 검토 기록이며, 실제 문의 발송·계정 변경·정산 처리를 수행하지 않습니다.
