# 청킹 전략과 RAPTOR 실습 가이드

교안 01 → 교안 02 → LV1 → LV2 순서로 진행합니다.

## 0. 준비

- [ ] 저장소 최상위에서 `uv sync`로 환경을 만듭니다. 패키지 버전은 최상위 `pyproject.toml`에 있습니다.

```bash
uv sync
```

- [ ] VS Code에서 노트북을 열고 `.venv`의 Python 3 (ipykernel) 커널을 선택합니다.
- [ ] `.env.example`을 `.env`로 복사하고 `OPENAI_API_KEY`를 넣습니다. LV1은 키가 필요 없습니다.
- [ ] 원본 PDF 18쪽(인쇄 12쪽)을 읽고, 청킹에는 여러 페이지를 연결한 긴 본문을 사용함을 확인합니다.
- [ ] PDF 9~20·25~42·49~66·71~93쪽의 연속 본문 네 편(71페이지)을 사용합니다. 구간 안의 짧은 절이나 문장을 미리 고르지 않습니다.

## 1. 진행 순서

- [ ] [교안 01](교안_01_청킹_전략.ipynb): 1~5절에서 다섯 전략의 청크 경계와 반환 문맥을 확인합니다. 절마다 함께 따라하기가 하나씩 있습니다. Auto-merging도 Chroma에서 잎을 검색하고 docstore에서 부모를 찾습니다.
- [ ] [교안 02](교안_02_재귀요약_RAPTOR.ipynb): 잎과 군집 → L1·L2 요약 → 전체 계층 검색. PDF 9~20쪽의 긴 본문을 직접 청킹한 뒤 잎으로 씁니다. 따라하기 셋은 앞 결과를 이어 씁니다.
- [ ] [LV1 기초](과제_LV1_기초.ipynb) 9문항
- [ ] [LV2 응용](과제_LV2_응용.ipynb) 7문항. 3번에서 웹 원문의 제목·URL·문자 위치를 부모와 함께 저장하고, 저장소 조회와 검색 출력으로 확인합니다. 5번 Auto-merging도 Chroma를 사용하며, 6번은 4번에서 만든 문장 목록을 이어 씁니다.

완성 코드는 수업이 끝난 뒤 강사가 공유합니다.

청크의 원문 위치·PDF 출처를 연결하는 보조 함수는 [util.py](util.py)에 있습니다. 교안·과제와 같은 폴더에 두고 사용합니다.

## 막혔을 때

- `FileNotFoundError`: 노트북이 있는 폴더에서 실행했는지 확인합니다.
- import 에러: 패키지를 설치한 `.venv`와 노트북 커널이 같은지 확인합니다.
- 인증·모델 접근 에러: `.env`의 `OPENAI_API_KEY`와, 필요하면 `OPENAI_CHAT_MODEL`을 확인합니다.
- 청크 위치가 안 맞음: `strip_whitespace=False`, `set_end_offsets`와 초기 파서 전체 결과의 `sequential=True`를 확인합니다. Auto-merging은 `nodes_to_documents`에 전체 계층 목록과 청킹 전 원문도 전달합니다.
- PDF 페이지가 다름: 문자 위치는 청킹 전 긴 본문 기준입니다. Parent-Child는 부모 분할 뒤 `add_pdf_pages`로 페이지 범위를 계산해 함께 저장합니다. Window·Auto-merging은 반환 문맥이 정해진 뒤 그 범위에 페이지를 붙입니다. 웹 문서를 쓰는 과제는 제목·URL·문자 위치로 출처를 확인합니다.
- PDF 51쪽 본문이 비어 있음: 본문이 이미지 도표인 페이지로, 텍스트 레이어에 내용이 없습니다. 원본 PDF를 열어 확인합니다.
- 병합이 안 됨: 검색된 자식 수가 그 부모 자식 수의 절반을 **넘어야** 부모로 바뀝니다.

## 완주 기준

- [ ] 다섯 전략의 검색 단위와 반환 단위를 구분해 말할 수 있다.
- [ ] 청크의 경계·길이와 반환 문맥이 달라지는 이유를 설명할 수 있다.
- [ ] L0 → L1 → L2의 입력과 출처 연결을 설명하고, 요약을 원문과 대조할 수 있다.
