# 청킹 전략과 RAPTOR

앞 단원의 `Document → 임베딩 → Chroma → 검색` 흐름에서 **어떻게 나누고 얼마나 돌려줄지**를 바꿔 봅니다. 기본 RAG의 한계에서 출발해 청킹 전략 다섯 가지를 같은 질문으로 비교하고, GPT 요약을 두 번 쌓는 RAPTOR 계층 검색을 만듭니다. [실습 가이드](실습_가이드.md)부터 시작하세요.

| 파일 | 내용 |
|---|---|
| [교안 01](교안_01_청킹_전략.ipynb) | 기본 RAG의 한계, Fixed·Semantic·Parent-Child·Sentence Window·Auto-merging, 같은 질문으로 근거 회수와 반환량 비교 |
| [교안 02](교안_02_재귀요약_RAPTOR.ipynb) | 직접 청킹한 PDF 원문을 잎 L0으로 사용 → 군집 요약 L1 → 요약의 요약 L2, 전체 계층 검색과 출처 확인 |
| [LV1 기초](과제_LV1_기초.ipynb) | 10문항, 모델 없이 경계·부모 ID·Window·병합 기준·근거 회수·요약 출처 |
| [LV2 응용](과제_LV2_응용.ipynb) | 8문항, Neo4j 릴리스 노트로 검색·문맥 확장·요약 연결 |

완성 코드는 수업이 끝난 뒤 강사가 공유합니다.

청크의 원문 위치·PDF 출처를 연결하는 보조 함수는 [util.py](util.py)에 있습니다. 교안·과제와 같은 폴더에 두고 사용합니다.

## 데이터

- 함께 따라하기: 고용노동부 「일·생활 균형을 위한 유연근무 활용 매뉴얼」(2024) PDF의 **연속 본문 4편, 71페이지, 56,045자**. PDF 9~20·25~42·49~66·71~93쪽이며, 원본은 `data/originals/`에 있습니다.
- 반복 머리말과 줄 끝 공백을 정리하고 연속 페이지를 연결했습니다. 제목·줄바꿈·목록·조건·예외는 유지하며, 문장이나 청크를 미리 만들어 제공하지 않습니다. 각 전략이 같은 긴 본문을 직접 나눕니다.
- `page_spans`는 본문의 문자 구간과 PDF 페이지를 연결하는 출처 정보입니다. PDF 51쪽의 이미지 도표는 추출할 본문 텍스트가 없어 원본으로 확인합니다.
- 시연은 가상 도서관 안내, 과제는 한국어 백과(LV1)·과거 Neo4j 릴리스 노트(LV2)입니다.
- 질문마다 참고 답안과 정답 근거 구간이 있습니다. 출처와 필드는 [데이터 안내](data/README.md)를 보세요.

교안 01은 본문 네 편으로 청킹과 검색 범위를 관찰합니다. 의미 경계의 두 설정 비교는 개념·도입 본문 한 편에서 하고, PDF 평가의 기본 범위는 본문별 두 질문씩 8문항입니다(전체 82문항으로 변경 가능). 교안 02는 PDF 9~20쪽 전체를 Recursive로 나눠 RAPTOR 잎으로 사용합니다.

## 준비

1. 저장소 최상위에서 `uv sync`로 환경을 만듭니다. 진행 순서는 [실습 가이드](실습_가이드.md)를 보세요.
2. `.env.example`을 `.env`로 복사하고 `OPENAI_API_KEY`를 넣습니다. LV1은 키 없이 진행합니다.
3. 노트북이 있는 폴더에서 실행합니다. 각 노트북은 새 커널에서 시작할 수 있습니다.

GPT는 `gpt-5.6-luna`(`OPENAI_CHAT_MODEL`로 변경 가능), 임베딩은 `text-embedding-3-large` 768차원입니다. 임베딩은 적재·검색 셀마다 새로 요청합니다. GPT 요청 수는 아래와 같고 다시 실행하면 늘어납니다.

PDF 비교에서는 4절의 Window 저장소를 재사용합니다. 본문과 설정을 바꾸었다면 앞의 해당 준비 셀부터 다시 실행하세요.

| 구간 | GPT 요청 |
|---|---|
| 교안 01, LV1 | 없음 |
| 교안 02 | 요약 8회 + 답변 1회 |
| LV2 | 요약 3회 |

## 결과를 읽는 기준

- 같은 질문·근거·K에서 **근거 구간 Recall과 반환 글자 수**를 함께 봅니다. 같은 K라도 전략마다 반환량이 다릅니다.
- RAPTOR 요약의 출처 연결(`leaf_ids`)은 요약 내용이 정확하다는 뜻이 아닙니다. 요약은 원문과 대조해 읽습니다.
