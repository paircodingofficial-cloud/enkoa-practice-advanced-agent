# 원문과 실습 데이터 안내

함께 따라하기는 인사팀의 유연근무 운영 문서 검색입니다. 짧게 선별한 문장을 청킹 입력으로 주지 않고, 실제 PDF의 연속된 긴 본문을 모든 전략에 공통으로 제공합니다. 각 전략이 본문을 직접 나누고 신청·승인 절차, 조건·예외와 여러 근거가 함께 남았는지 비교합니다.

## 함께 따라하기: 실제 PDF의 연속 본문

- 발행: 고용노동부, 「일·생활 균형을 위한 유연근무 활용 매뉴얼」, 2024년 10월.
- [공식 게시물](https://www.worklife.kr/website_renew/index/newsroom/press_releases_view.asp?GUID=B1C5B341-D745-40C5-9D6B-769F3D75E921) · [공식 다운로드](https://www.worklife.kr/library/server/common.attach.download.asp?GUID=DC573FB9-EB3D-45F5-AC37-EC7F9EF77F2B) · [배포 원본](originals/MOEL_flexible_work_manual_2024.pdf) (2026-09-18 내려받음, 167쪽, SHA-256은 `pdf_manifest.json`).
- 네 개 구간의 **71개 PDF 페이지**를 빠짐없이 순서대로 읽습니다. 장 표지·빈 구분 페이지와 선택 범위 뒤의 기업 사례는 입력에 포함하지 않습니다.
- 범위 안의 설문·규정 예시·표·양식도 그대로 남깁니다. 질문에 필요한 문장만 다시 골라 입력을 짧게 만들지 않습니다.
- 2024년 판본을 읽는 검색 연습입니다. 현행 제도나 법률 판단으로 일반화하지 않습니다.

| doc_id | 연속 본문 | PDF 페이지 | 인쇄 쪽수 | 글자 수 |
|---|---|---:|---:|---:|
| hr_flexible_intro | 유연근무 개념·유형·도입 설계 | 9–20 | 3–14 | 8,235 |
| hr_staggered_work | 시차출퇴근 개념·도입·규정·Q&A | 25–42 | 19–36 | 13,954 |
| hr_selective_work | 선택근무 개념·도입·Q&A | 49–66 | 43–60 | 13,731 |
| hr_remote_work | 재택·원격근무 개념·관리·규정 설계 | 71–93 | 65–87 | 20,125 |

총 본문은 **56,045자**입니다. 페이지를 연결할 때 넣은 두 줄바꿈도 포함한 값이며 토큰 수가 아닙니다.

## PDF에서 본문을 만드는 방법

1. pypdf의 기본 텍스트 추출로 각 페이지를 읽습니다.
2. 이 판본에서 반복되는 쪽수·발행처·측면 장 제목을 본문 앞부분에서 제거합니다.
3. 각 줄 오른쪽의 공백만 지우고, 본문의 줄바꿈·들여쓰기·제목·목록 순서를 유지합니다. 문장을 미리 분리하거나 숫자·조건·철자를 교정하지 않습니다.
4. 같은 구간의 페이지를 두 줄바꿈으로 연결합니다. 각 페이지 본문의 시작·끝 위치는 `page_spans`에 남깁니다.

`practice_docs.json`이 청킹 입력입니다. PDF 자료에는 `sentences` 필드가 없습니다. `practice_pdf_pages.json`의 `text`는 머리말을 포함한 페이지 추출 원문, `cleaned_text`는 위 규칙으로 정리한 본문입니다. `cleaned_text`는 해당 문서의 `text[start:end]`와 같습니다. 제거한 머리말은 `removed_header`에 남깁니다.

PDF 51쪽(인쇄 45쪽)은 근무시간 운영 예시를 담은 이미지 도표라 본문 텍스트가 추출되지 않습니다. 해당 페이지 기록은 `text_status="no_extractable_body"`로, 페이지 구간은 `start == end`로 보존합니다. OCR로 내용을 채우지 않으며 기존 82개 질문의 근거는 이 페이지에 없습니다.

텍스트 추출은 PDF의 시각적 배치를 완전히 복원하지 않습니다. 긴 문장의 시각적 줄바꿈, 불규칙한 자간, 표의 읽기 순서, 제목·규정 예시의 반복, 원문의 표기와 오탈자가 남습니다. 표의 열이나 이미지 안 문자는 원본 PDF를 함께 확인해야 합니다.

## 데이터별 역할

| 파일 | 성격 | 원문 수 | 문장·항목 수 | 출처 |
|---|---|---:|---|---|
| demo_docs.json | 개념 데모 | 4 | 16 | 직접 작성한 가상 도서관 안내 |
| practice_docs.json | 함께 따라하기 | 4 | 미리 나누지 않음 | 고용노동부 실제 PDF의 연속 본문 |
| lv1_docs.json | 한 단계 연습 | 5 | 24 | 단위 프로젝트 2 자료(한국어 백과) |
| lv2_docs.json | 검색·확장·요약 연결 | 5 | 25 | 단위 프로젝트 2 자료(Neo4j 릴리스 노트) |
| lv3_docs.json | 후속 단원 공유 원문 | 6 | 23 | 파이썬 라이브러리 문서(pandas 사용자 가이드) |

LV1은 한국어 백과 도입부, LV2는 과거 Neo4j 릴리스의 도입·변경 항목(최신 설치 안내가 아님)입니다. pandas 원문과 질문(`lv3_docs.json`, `lv3_questions.json`)은 후속 단원 제작에서 공유하는 자료로 보관하며 이 단원의 과제에는 사용하지 않습니다. 이 자료들의 기존 본문과 문장·항목 목록은 유지합니다. 원문 URL과 해시는 각 기록과 `sources.json`에 있습니다.

## 주요 필드

| 필드 | 의미 |
|---|---|
| doc_id / title | 원문 ID / 원문 제목 |
| text | 전략들이 직접 나누는 입력 본문 |
| sentences | PDF 외 자료에 제공하는 문장·항목 목록(`sentence_id`, `text`, `start`, `end`), PDF에는 없음 |
| start / end | 해당 text 안의 시작·끝 문자 위치(끝은 포함하지 않음) |
| url / source | 공식 URL / 원본 위치 |
| pdf_file | 배포 원본 PDF의 data 기준 상대 경로 |
| pdf_start_page / pdf_end_page | PDF 뷰어에서 1부터 세는 연속 범위의 첫·마지막 페이지 |
| printed_start_page / printed_end_page | 본문에 인쇄된 첫·마지막 쪽수 |
| page_spans | 페이지별 `pdf_page`, `printed_page`, `start`, `end`. start/end는 연결된 본문 text 기준 |
| sha256 | text의 해시 |

페이지 사이에 삽입한 두 줄바꿈은 어느 페이지 구간에도 포함하지 않습니다. 문서·청크가 여러 페이지에 걸치면 그 문자 구간과 겹치는 페이지들을 출처로 표시합니다. 길이가 0인 페이지 구간에는 인용할 본문이 없습니다.

## 보관 중인 질문과 출처 자료

현재 교안·과제에서는 검색 품질 평가를 하지 않으며, 아래 질문 묶음을 실행에 사용하지 않습니다. `*_questions.json`은 기존 출처 확인용 자료로 보관합니다. 질문·참고 답안·근거는 원문을 읽고 작성했습니다. `evidence`는 **원문에서 직접 지정한 고정 구절과 문자 구간**이며, 검색 결과를 보고 정답을 바꾸지 않았습니다.

PDF의 기존 **82개 질문·101개 근거**는 의미를 유지했습니다. 질문·유형·참고 답안은 그대로 두고, 기존 짧은 발췌 ID를 긴 본문 ID로 연결했습니다. 인용문은 새 본문의 줄바꿈·공백을 그대로 담으므로 문자 위치는 새로 계산했습니다. 공백을 제외한 근거의 글자는 바꾸지 않았습니다. 규정 예시에서 같은 표현이 반복되더라도 처음 지정한 PDF 페이지의 근거를 사용합니다.

| 파일 | 역할 | 질문 수 | 근거 구간 수 |
|---|---|---:|---:|
| [demo_questions.json](demo_questions.json) | 도서관 원리 설명 | 4 | 5 |
| [practice_questions.json](practice_questions.json) | PDF 질문·출처 보관 | 82 | 101 |
| [lv2_questions.json](lv2_questions.json) | Neo4j 질문·출처 보관 | 30 | 39 |
| [lv3_questions.json](lv3_questions.json) | 후속 단원 공유 질문 | 31 | 43 |

| 질문 필드 | 용도 |
|---|---|
| question_id / question | 질문 ID와 검색 질문 |
| question_type | `사실확인`·`조건·예외`·`절차·적용`·`비교·종합` 중 하나 |
| reference_answer | 근거만으로 쓴 참고 답안(GPT 출력이 아님) |
| evidence | 출처 doc_id, 정확한 quote, 시작·끝 위치(원문 대조용) |
| evidence.pdf_pages / evidence.printed_pages | PDF 근거가 실제 놓인 뷰어 페이지 / 인쇄 쪽수 목록 |

검색 인덱스에는 원문 `*_docs.json`만 넣습니다. 참고 답안이나 근거를 검색 문서에 섞지 않습니다. 참고 답안과 GPT 답변을 자동으로 비교하지 않습니다. 파일 해시와 개수는 [golden_manifest.json](golden_manifest.json)에 있습니다.

배포 파일에는 GPT 답변·요약·임베딩이 없습니다. 모델 결과는 실행할 때 만들어집니다. 원문의 권리와 이용 조건은 각 출처를 따릅니다.
